### Native-slot question (his follow-up, answered)

He asked why a native tool call cannot leak into user-visible text and "where does it go". Answer:
it is a **typed field on a multi-field message object**, not prose — OpenAI `message.tool_calls`
(with `content: null` on that turn), Anthropic a `tool_use` content block beside `text` blocks, Gemini
a `functionCall` part. The user-facing renderer reads the text field only, so non-leakage is
*structural*, not a filtering step. Contrast: prompt-based JSON puts the call and the prose in the
same string, so you can only filter heuristically afterwards. Lifecycle: assistant turn carries the
call slot → host executes → host appends a `tool` role message with the matching id → re-request; the
model then sees both turns, and they do come back into its input as typed fields. Also flagged that
reasoning models have a *third* slot (reasoning/thinking) which is likewise not user-visible — do not
conflate it with the tool-call slot.
